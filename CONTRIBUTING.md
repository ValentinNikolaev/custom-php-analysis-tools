# Contributing

Thank you for helping improve the PHP analysis tools catalog. Contributions can
correct catalog metadata, propose tools, improve the generated site, or improve
the maintenance scripts and tests.

By participating, you agree to follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Before You Start

- Search existing issues and pull requests before opening a duplicate.
- Use an issue form for a catalog correction or a new tool proposal when you are
  unsure whether a pull request is appropriate.
- Keep each pull request focused on one logical change.

## Development Setup

The project uses Python 3.12 and the Python standard library. No dependency
installation is required.

Run the test suite from the repository root:

```shell
python -m unittest discover -s tests
```

Build the site locally into a disposable directory:

```shell
python scripts/generate_site.py --output site-dist
```

## Catalog Changes

`common/catalog/*.yaml` is the source of truth for published catalog entries.
`common/candidates/*.yaml` contains discoveries that still need editorial
review. Do not edit generated catalog tables in `README.md`,
`EDITOR-CHOISE.md`, or `site/` as a substitute for changing the source data.

When adding or updating an entry:

1. Use a lowercase, hyphenated filename matching the entry's `slug`.
2. Use one of the categories defined in `scripts/catalog_lib.py`.
3. Provide the official project and repository URLs when available.
4. Keep descriptions factual and concise; avoid promotional claims.
5. Do not set `editor_choice: true` in an entry. Editors' Choice membership is
   maintained in `common/editor-choice.yaml`.
6. Add a short pro, con, and official source URL to `common/pros-cons.yaml`.
   These summaries are editorial copy: update them manually and do not derive
   or overwrite them during metadata refreshes.
7. Regenerate the derived files:

   ```shell
   python scripts/generate_editor_choice.py
   python scripts/generate_readme.py
   python scripts/generate_site.py --output site-dist
   ```

The full metadata refresh contacts GitHub, Packagist, and project websites. Run
it only when the contribution needs current external metadata:

```shell
python scripts/full_workflow.py --skip-discovery
```

## Code and Workflow Changes

- Add or update tests for behavior changes.
- Preserve the deterministic generated output.
- Keep `.codex/` as the source of truth for agent configuration; `.claude/` is
  generated by automation.
- Never commit tokens, credentials, private vulnerability details, or generated
  `site-dist/` output.

## Pull Request Checklist

Before submitting a pull request:

```shell
python -m unittest discover -s tests
git diff --check
git status --short
```

Explain what changed, why it changed, and which verification commands you ran.
